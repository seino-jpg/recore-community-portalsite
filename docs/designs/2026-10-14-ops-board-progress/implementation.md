## 手本にする実装

| 層 | ファイル | 理由 |
|---|---|---|
| DB | `db/ops-schema.sql`・`scripts/apply-ops-schema.mjs` | 何度流しても同じ結果になる DDL。制約の張り替えも同じファイルに足す（開発用 DB で制約名 `ops_tasks_status_check` を確認済み） |
| API | `api/_lib/ops-core.js` の `STATUSES`・`normalizeTask` | 状態の検査は既にここ1か所 |
| 画面 | `ops.html` の `render`・`taskRow`・`changeStatus`・タブの URL を持たない作り | 前回の流儀（1ファイル・テンプレート文字列・`esc`・`data-*` のクリック委譲）に合わせる。URL の読み書きは `history.replaceState` だけを足す |
| テスト | `test/ops.test.mjs` | API のユースケースは node:test＋開発用 DB。画面はテストの基盤が無いので手で確かめる（前回と同じ。検証用サーバーはコミットしない） |

実装で決めたこと（設計の範囲内）：「確認した」はもう一度押すと外れる。打ち合わせの担当の並びはモードに入ったときに決め、モード中に件数が変わっても並びを動かさない（新しい担当は末尾に足す）。

検証のあと、開発用 DB の ops_tasks は検証用の架空データ（23件）のまま。`npm test` が毎回空にするので残しても害は無い。
