### 2. 参加申し込み（apply.html）

イベントカードの「参加を申し込む」ボタンから遷移する専用ページ。

- 対象イベント：関東コミュニティ Vol.4（ブックオフ出品倉庫 見学会）
- 入力項目：会社名・お名前・役職（経営者／部長・課長／その他）・メールアドレス・電話番号・当日の交通手段（公共交通機関／お車（駐車場を希望）／お車（駐車場は不要））が必須、ご質問・ご要望は任意
- 申込締切：`EVENTS` の `deadline`（YYYY-MM-DD）の 23:59 JST を過ぎるとフォームを非表示にして受付終了メッセージを出す
- 複数名で参加する場合は1名ずつ申し込む運用（参加人数の入力欄は設けていない）
- 送信先は Google Apps Script のWebアプリ（`APPLY_ENDPOINT` 定数で指定）
- 申し込み内容はスプレッドシート「RECOREコミュニティ 参加申し込み」のイベント別タブ（現在は `【関東】vol.4`）に追記される
- 申込者へ自動返信メールを送信、運営へは Slack「recoreコミュニティ運営」チャンネルに通知（Slackが使えないときはメールにフォールバック）
- GAS のソースは `~/gas-community-form`（clasp管理）

#### 新しいイベントのフォームを増やす手順

イベントごとに申し込みタブを分ける運用。3ファイルを編集するだけで増やせる。

1. **GAS**（`~/gas-community-form/Code.js`）の `EVENT_SHEETS` に1行足す
   ```js
   var EVENT_SHEETS = {
     'kanto-vol4': '【関東】vol.4',
     'kansai-vol2': '【関西】vol.2'   // 追加
   };
   ```
   反映は `clasp push -f` → `clasp redeploy <デプロイID>`（デプロイIDは変えないこと。変えると送信先URLが変わる）

2. **apply.html** の `EVENTS` に1ブロック足す（キーは手順1と揃える）
   ```js
   'kansai-vol2': {
     title: '関西コミュニティ第2回イベント｜◯◯',
     name: '関西コミュニティ第2回イベント（◯◯）',
     lead: '関西コミュニティ第2回イベントへのお申し込みはこちらから。<br>受付後、担当より詳細をご連絡します。',
     date: '2026年◯月◯日（◯）00:00〜00:00',
     place: '会場名（住所）',
     detail: '内容の1行目\n内容の2行目',
     deadline: '2026-09-30',   // 申込締切（この日の23:59 JSTで受付終了）
     transportNote: '駐車場に関する補足'
   }
   ```

3. **index.html** のイベントカードのボタンを `apply.html?event=kansai-vol2` にする

記録先のタブは最初の申し込みが入った時点で自動作成される（ヘッダー・書式つき）。手で作っておいても構わない。
キーが未登録・未指定の申し込みは `その他` タブに入るので、設定漏れでも取りこぼさない。

**新しいイベントのLPを増やすとき**

1. `kanto-vol4.html` を複製して内容を差し替える（スタイルはファイル内で完結している）
2. `apply.html` の `EVENT_LP` にキーとファイル名を1行足す — 申込カードからLPへの導線が出る
3. `index.html` のイベントカードに「イベント詳細を見る」ボタンを足す
4. `vercel.json` の `rewrites` に拡張子なしURLを1行足す

## セットアップ

### ローカル開発

```bash
git clone https://github.com/seino-jpg/recore-community-portalsite.git
cd recore-community-portalsite
python3 -m http.server 8080
# http://localhost:8080/index.html
```

ローカルでは `vercel.json` の rewrite が効かないため、拡張子つき（`kanto-vol4.html`）でアクセスする。

## デプロイ（Vercel）

- **プロジェクト** — `recore-community-portalsite`（Vercel アカウント: seino-jpg）
- **フレームワーク** — なし（静的HTMLをそのまま配信。ビルドコマンドなし）
- **連携ブランチ** — `main` への push で自動デプロイ、それ以外のブランチはプレビューURL

`vercel.json` の rewrite により、拡張子なしのURLでも配信される。

| 配信URL | 実ファイル |
|---|---|
| `/` | `index.html` |
| `/kanto-vol4` | `kanto-vol4.html` |
| `/apply?event=kanto-vol4` | `apply.html` |

## 更新方法

```bash
git add .
git commit -m "Update: [変更内容]"
git push origin main
```

push すると Vercel が自動でデプロイします（数十秒）。

### 移行前のリポジトリについて

移行元の `ueda-recore/recore-portalsite`（GitHub Pages）は上田さん個人アカウント配下にあり、
`https://ueda-recore.github.io/recore-portalsite/` でまだ公開されている。
外部に配ったリンクの差し替えが済むまでは、日程など公開情報の変更は**両方に反映すること**。
`upstream` remote として設定済み：

```bash
git remote -v   # origin=seino-jpg（正本） / upstream=ueda-recore（移行元）
```
